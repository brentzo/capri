# docs

Project documentation, in two layers.

- [`requirements/`](requirements/) - business requirements (BR-*): what we are building end-to-end and why, as user stories with user-centric Gherkin acceptance scenarios.
  This is the "what and why".
- [`specs/`](specs/) - the detailed component specs (HC-*): how each part works.
  See [`specs/INDEX.md`](specs/INDEX.md) for the registry.
  This is the "how".

The top-level [`../SPEC.md`](../SPEC.md) is the overview and decision log that the `specs/` documents elaborate.
